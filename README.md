# 답장노트 · Reply Note

Electron + React + TypeScript로 만든 개인용 카카오톡 답장 초안 앱입니다. Mac 카카오톡에서 **사용자가 직접 열어둔 일반 1:1·단체 채팅방**을 Swift 접근성 모듈로 읽으며, Windows UI Automation 읽기 모듈을 시험 지원합니다. Windows 카카오톡 실기 검증은 아직 완료하지 않았습니다. 창을 앞으로 가져오거나 마우스·키보드·클립보드를 조작하지 않습니다. 화면 캡처나 OCR을 사용하지 않습니다.

## 실행

필요한 환경: Node.js 22.13 이상, 로그인된 OS 네이티브 Codex CLI. Mac은 Xcode Command Line Tools(`swiftc`)가 필요합니다. Windows는 Windows PowerShell 5.1과 .NET Framework UI Automation을 사용하며 별도 C++ 빌드 도구는 필요하지 않습니다. 의존성은 `npm ci`로 설치합니다.

```sh
npm run dev
```

개발 서버를 별도로 실행할 필요가 없습니다. 위 명령이 앱 내부 Swift 라이브러리·Node-API 모듈 컴파일, Electron 코드 컴파일, Vite와 Electron 실행을 담당합니다. 개발 중 Electron 코드를 수정하면 다시 실행해야 합니다. 화면 코드는 자동 반영됩니다.

```sh
npm run pack       # release/mac-arm64/Reply Note.app (현재 Mac 아키텍처 기준)
npm run dist:mac   # Mac용 ZIP
npm run demo       # 실제 대화/모델/전송 없이 UI와 대기·취소·초안 흐름을 시험
```

개인용 로컬 빌드이며 Mac에는 ad-hoc 서명을 적용합니다. 공인 배포 서명·공증은 설정하지 않았습니다.

## 첫 연결

1. 카카오톡을 실행하고 로그인합니다. 감지할 **일반 1:1·단체 채팅방들을 각각** 직접 엽니다. 나와의 채팅은 수신 확인용으로 추가할 수 있습니다.
2. Reply Note의 `연결 설정`에서 `시스템 설정 열기`를 누르고, macOS `개인정보 보호 및 보안 → 손쉬운 사용`에서 Reply Note에 접근을 허용합니다. 개발용 Electron과 패키징된 앱은 서로 다른 권한으로 취급될 수 있습니다. 읽기 모듈은 앱 내부에서 실행되며 별도 실행 파일에 권한을 줄 필요가 없습니다. 기존 Codex/컴퓨터 사용 도구의 권한은 앱에 자동으로 이전되지 않습니다.
3. 열린 채팅방 새로고침을 눌러 창 이름을 **정확하게** 입력·선택하고 `채팅방 추가`를 누릅니다. 최대 20개까지 저장할 수 있습니다. 동명이인 방은 창 이름을 고유하게 바꿔야 합니다.
4. 공통 프롬프트를 저장하고 `전체 감지 시작` 또는 각 방의 재생 버튼을 누릅니다. 목록에서 대화를 선택하면 해당 방의 메시지와 초안을 볼 수 있습니다. 기존 대화는 문맥으로만 사용하며, 첫 연결 시 과거 메시지에 대한 초안을 만들지 않습니다.
5. 연결 확인 후 카카오톡을 `⌘H`로 숨겨도 됩니다. 채팅방 창을 닫거나 최소화하면 읽지 못할 수 있습니다.

접근성으로 메시지 본문, 순서, 표시된 시각을 수집합니다. 상대 프로필과 말풍선 위치를 이용해 발신 방향을 분류하며, 판별하지 못한 새 메시지는 자동 생성하지 않고 상태를 표시합니다. 카카오톡 버전·창 크기·레이아웃에 따라 분류를 추가 보정해야 할 수 있습니다. **나와의 채팅도 연결할 수 있으며 휴대폰 메시지 수신 확인과 수동 초안 생성을 지원합니다. 이 방의 자동 생성은 꺼져 있으며, `실제 대화 초안 만들기`를 누르면 최근 대화를 OpenAI에 전달해 수동 초안을 만듭니다. 마지막 메시지를 상대가 보낸 것으로 가정하며 결과는 앱에만 보관합니다. 일반 1:1 대화와 참여자를 등록한 단체방에서 자동 초안을 생성합니다.**

## 처리 규칙

- 약 2초마다 감지가 켜진 저장 채팅방들을 순서대로 확인합니다(실제 주기는 읽기 응답 시간에 따라 길어질 수 있습니다). 한 번에 최대 60개 로드된 행만 살펴보고 텍스트·사진·파일 표식을 포함한 메시지 20개를 반환하며, 읽기 시간 초과는 연결 오류로 표시합니다. 카카오톡에 키·클릭·창 활성화 요청을 보내지 않습니다.
- 1:1은 상대의 마지막 새 메시지 후 10초 기다립니다. 단체방은 등록한 질문자별로 독립적으로 10초를 기다리고, 같은 질문자의 연속 메시지만 묶습니다.
- 1:1은 내 답장이 관찰되면 대기·생성을 취소합니다. 단체방은 등록된 선생님의 메시지가 오면 내용에 관계없이 그 방의 모든 대기·생성을 취소합니다. 내 메시지를 취소 신호로 쓰려면 선생님에 `나`를 등록합니다.
- 생성 중 같은 질문자의 메시지가 추가되면 그 질문자의 작업만 취소하고 다시 10초 기다립니다. 다른 질문자의 작업은 유지합니다.
- 전달 직전에 대화를 다시 읽습니다. 1:1은 새 메시지가 있으면 초안을 버립니다. 단체방은 같은 질문자의 추가 메시지나 선생님 메시지, 발신자 미확인·연결 오류가 있으면 해당 규칙에 따라 취소합니다.
- 연결 끊김·절전·히스토리 재로딩·대상/프롬프트 변경 시 기존 작업을 취소합니다. 재연결은 새 기준을 잡고 이후 메시지부터 처리합니다. 끊긴 동안의 메시지를 소급 생성하지 않습니다.
- 각 방의 최근 메시지 20개를 표시하고, 수집된 대화를 최대 500개·20만 자까지 누적 보관합니다. 전체 최근 초안은 최대 20개를 저장합니다. 앱 재시작 시 감지는 일시정지입니다.
- 카톡 첨부파일을 자동으로 다운로드하지 않습니다. 사용자가 질문에 직접 연결한 사진·PDF·문서만 분석에 사용하며 이모티콘은 해석하지 않습니다. 읽음 처리될 수 있습니다.
- 상대방에게 자동 답장을 보내는 기능은 없습니다. 앱 창을 닫아도 메뉴 막대에서 계속 실행되며, 종료는 메뉴 막대의 `종료`를 사용합니다.

## Codex

설치된 `codex exec`를 읽기 전용 샌드박스로 실행합니다. 셸 문자열을 조립하지 않고 인자와 표준 입력을 분리합니다. 대화를 명령줄 인자나 로그에 기록하지 않습니다. 임시 작업 디렉터리에서 `--ephemeral`로 실행하고 출력 파일은 읽은 뒤 삭제합니다. 설치된 CLI의 `--ignore-user-config`, `--ignore-rules` 옵션을 사용하므로 이를 지원하는 CLI가 필요합니다. 사용자 MCP·훅·프로젝트 설정을 가져오지 않으며 인증은 기존 Codex 로그인 정보를 사용합니다.

Codex CLI가 없으면 설치 후 `codex login`을 완료하세요. Finder에서 실행할 때 PATH가 다를 수 있어 실행 파일 절대 경로를 설정할 수 있습니다. 모델 선택창에서 현재 Codex가 표시하는 모델을 선택할 수 있습니다. `Codex 기본값`은 목록에서 기본으로 표시된 모델을 실행 시 명시적으로 전달합니다. 기본 모델 정보를 읽지 못하면 임의의 모델로 실행하지 않고 선택 안내를 표시합니다. **CLI는 로컬 프로세스지만 추론은 OpenAI 서비스에서 수행되므로 프롬프트와 대화가 외부로 전송됩니다.**

## 카카오톡 ‘나에게 보내기’

기본값은 앱에서 초안 표시 + 로컬 알림입니다. 카카오톡 `나와의 채팅` 전달은 [공식 메시지 API](https://developers.kakao.com/docs/ko/kakaotalk-message/rest-api)를 사용합니다. 데스크톱 카카오톡 로그인과 API 인증은 별개입니다.

1. 카카오디벨로퍼스 앱을 준비하고, 메시지 동의항목 `talk_message`를 설정합니다.
2. 해당 권한에 동의한 **사용자 액세스 토큰**을 발급합니다. 관리자 키나 REST API 키가 아닙니다.
3. 연결 설정에서 토큰을 저장하고 `카카오톡 나와의 채팅에도 전달`을 선택한 뒤 설정을 저장합니다.

토큰은 Electron `safeStorage`로 암호화합니다. 안전한 저장소를 사용할 수 없으면 저장을 거부합니다. 토큰은 화면·로그·렌더러 응답으로 돌려주지 않습니다. 현재 버전은 OAuth 로그인/토큰 자동 갱신을 구현하지 않아 만료 시 직접 교체해야 합니다. API 앱의 도메인·템플릿·권한·쿼터 설정도 필요할 수 있습니다. 텍스트 템플릿 길이(200자)에 맞게 긴 초안은 잘림 안내와 함께 전달하며 전체 초안은 앱에 남습니다. 실패하면 앱에 이유를 표시하고 자동 재전송하지 않습니다.

## 저장과 권한

일반 실행 데이터는 Electron userData 디렉터리(보통 `~/Library/Application Support/Reply Note/`)에 있습니다. `state.json`에 공통 설정·저장한 채팅방 목록·방별 최근 대화·초안이, `kakao-token.enc`에 암호화된 토큰이 있습니다. 대화 기록 자체는 로컬 JSON 평문이므로 같은 사용자 계정의 프로세스가 읽을 수 있습니다. 기록 삭제 버튼은 대화와 초안을 삭제하고 감지를 중지하며 프롬프트와 설정은 유지합니다. Codex가 실행 중이었다면 취소됩니다. 데모는 별도의 임시 디렉터리를 사용합니다.

## 플랫폼 상태

UI, 저장, Codex 실행, 감지 워크플로와 전송은 공통 TypeScript 코드입니다. `Reader` 인터페이스만 OS별로 교체합니다. **Mac은 실제 접근성 수신 연결을 확인했고, Windows는 UI Automation 모듈을 구현한 시험 지원 상태입니다.** Windows 실제 카카오톡의 메시지 노출·참여자 표시·발신 방향·가려진 창 갱신 여부는 실기 검증 전입니다. 합성 구조 테스트와 Windows 설치 파일 생성만으로 실제 대화 수집이 검증된 것은 아닙니다.

## 0.1.1 연결 오류 수정

- 별도 Swift 실행 파일 대신 앱 내부 Node-API/Swift 라이브러리에서 읽어 Reply Note에 허용된 접근성 권한을 사용합니다.
- 저장·새로고침·앱 시작 시 선택한 채팅방을 실제로 확인합니다. 열린 창 목록 조회 성공만으로 대화가 연결됐다고 표시하지 않습니다.
- 권한, 이름 불일치, 닫힌 방, 지원하지 않는 방, 일시정지를 구분해 표시합니다. 열린 채팅방 이름 버튼으로 정확한 제목을 선택할 수 있습니다.
- 나와의 채팅은 수신 확인 전용으로 지원하며 자동 초안 생성과 전송은 차단합니다.

## 0.2.0 여러 채팅방과 초안 생성 확인

- 여러 채팅방을 저장하고, 방별 또는 전체 감지를 시작·정지합니다. 화면에서 다른 방을 선택해도 진행 중인 다른 방의 대기·생성은 유지됩니다.
- 대화 문맥(최대 20개), 10초 대기, 직접 답장 시 취소, 생성 중 재시작은 방별로 독립적으로 처리됩니다. 한 방이 닫혀 있어도 다른 방을 계속 확인합니다.
- 공통 프롬프트·모델·전달 방식 변경은 모든 방의 생성을 취소하고 감지를 정지합니다. 최근 대화는 유지됩니다. 새 방 추가나 화면 선택은 기존 방의 작업을 취소하지 않습니다.
- 기존 단일 채팅방 저장 파일은 채팅방 목록과 방별 기록으로 자동 이전합니다. 재시작 후에는 모든 방이 일시정지입니다.
- `초안 생성 테스트` 버튼은 고정된 가상 대화 2개와 저장한 공통 프롬프트로 **실제 Codex CLI**를 실행합니다. 실제 카카오톡 대화를 읽거나 테스트 초안을 카카오톡에 전송하지 않습니다. 결과는 `테스트` 표시와 함께 앱에 보관됩니다.
- 테스트 실행 중 표시, 실패 이유, 생성된 실제 초안을 앱에서 확인할 수 있습니다. 테스트 버튼은 데모 모드에서 비활성화됩니다.
- 채팅방 목록의 제거 버튼은 해당 방만 정지·삭제합니다. 공통 설정과 다른 방은 유지됩니다. 이전에 생성된 초안은 전체 기록 삭제 전까지 남아 있습니다.

## 0.3.0 모델 선택

- `연결 설정 → Codex 연결 → 답장 생성 모델`에서 모델을 선택하고 설정을 저장합니다. 모든 채팅방에 공통 적용됩니다. 기존 설정 저장 동작과 같이 감지가 정지되므로 저장 후 필요한 방의 감지를 다시 시작합니다.
- 앱 시작 또는 새로고침 버튼으로 설치된 Codex의 `app-server`에 `initialize → initialized → model/list`를 요청합니다. 현재 로그인·클라이언트가 반환하는 목록을 표시하며 모델 이름을 하드코딩하지 않습니다. 모델 조회는 대화 스레드를 만들거나 프롬프트를 보내지 않습니다.
- 목록에 없는 모델은 `모델 ID 직접 입력`으로 지정할 수 있습니다. 선택한 모델은 `codex exec --model` 인자로 전달합니다. 모델이 거절되면 오류를 표시하며 다른 모델로 자동 변경하지 않습니다.
- `초안 생성 테스트`로 같은 공통 프롬프트와 가상 대화에서 선택 모델을 시험할 수 있습니다. 초안 및 최근 기록에 실행 시 요청한 모델 ID를 남깁니다. 이전 초안에는 모델 정보가 없을 수 있습니다.
- 앱의 자동 기본값은 조회된 모델 카탈로그의 기본값을 사용합니다. 사용자별 `config.toml`은 초안 실행에 로드하지 않으므로 사용자가 별도로 지정한 전역 기본 모델과는 다를 수 있습니다. 고정된 모델을 원하면 이름을 직접 선택하세요.

모델 조회 방식은 [공식 App Server 문서의 model/list](https://learn.chatgpt.com/docs/app-server#list-models-modellist)를 따릅니다. 모델 접근 권한·가용성은 현재 Codex 로그인과 서비스 상태에 따라 달라지며 실제 사용 여부는 생성 테스트로 확인할 수 있습니다.

### effort와 오류 확인

`연결 설정 → Codex 연결`에서 모델을 선택한 다음 `추론 강도 · effort`를 선택하고 설정을 저장하세요. 선택 가능한 수준과 기본값은 해당 모델의 `supportedReasoningEfforts` 및 `defaultReasoningEffort` 응답을 사용합니다. 모델을 바꾸면 이전 모델의 effort 선택은 기본값으로 초기화됩니다. 같은 모델에서 `초안 생성 테스트`로 차이를 비교할 수 있습니다.

저장한 effort는 `-c model_reasoning_effort="선택값"`으로 CLI에 전달하며 초안 기록에도 남깁니다. 지원되지 않는 조합은 실행 전에 안내합니다. 모델 기본값 선택 시에도 카탈로그의 기본 effort를 확인할 수 있으면 명시적으로 요청합니다.

표시 이름 `GPT-6.1-Sol`과 실행 ID `gpt-6.1-sol`은 구분됩니다. 카탈로그에 정확히 대응하는 표시 이름이나 대소문자 표기는 실행 ID로 정규화하며, 알 수 없는 모델을 다른 모델로 교체하지 않습니다. Codex 구조화 오류를 이용해 모델 거절, effort 거절, 로그인, 사용량, 네트워크 오류를 구분하며 원시 오류·대화·인증 정보는 로그에 저장하지 않습니다.

나와의 채팅 수신 시험은 메인 목록의 표시 상태와 독립적으로 채팅방 자체의 서랍/참여자/통화 컨트롤을 확인합니다. 분류가 불확실한 창에 자동 초안 생성 권한을 부여하지 않으며, 이 수신 전용 모드는 모델을 실행하지 않습니다. 연결 카드에도 실제 오류 종류를 표시합니다.


## 0.4.0 Windows 시험 지원

Windows 10/11 x64용 설치 패키지를 구성했습니다. Mac에서 Windows 설치 파일을 만들 수 있지만, 네이티브 UI Automation 모듈의 컴파일·시작과 실제 카카오톡 연결은 Windows에서 별도 확인해야 합니다.

### Windows 사용 순서

1. Windows용 카카오톡에 로그인하고 일반 1:1 채팅방을 **별도 창**으로 엽니다. 창을 닫거나 최소화하지 않고 다른 창 뒤에 유지합니다. Windows에는 Mac의 `⌘H` 숨기기 절차를 적용하지 않습니다.
2. Windows 네이티브 Codex CLI를 설치하고 PowerShell에서 `codex login`을 완료합니다. WSL 안에만 설치된 CLI·로그인은 사용하지 않습니다. [공식 설치 문서](https://learn.chatgpt.com/docs/cli)를 참고하세요.
3. Reply Note와 카카오톡 모두 같은 로그인 사용자로 일반 실행합니다. 관리자 실행 여부가 서로 다르면 읽지 못할 수 있습니다. 앱이 권한을 자동 상승시키거나 시스템 실행 정책을 바꾸지는 않습니다.
4. 연결 설정에서 열린 창 목록을 새로고침하고 정확한 제목으로 채팅방을 추가합니다. 공통 프롬프트·모델·effort를 저장하고 가상 대화 생성 테스트로 Codex 연결부터 확인합니다.
5. 앱에 표시된 실제 메시지와 `나`/상대 구분을 카카오톡과 비교한 뒤 감지를 시작합니다. 새 상대 메시지가 오면 10초 후 초안이 나오는지, 직접 답장하면 대기·생성이 취소되는지 확인합니다. 실제 Windows 발신 방향 판별은 이 단계의 검증이 필요합니다.

읽기 모듈은 숨겨진 Windows PowerShell 프로세스 하나에서 C# UI Automation 코드를 로드합니다. 별도 서버나 공기계가 필요하지 않습니다. 창 활성화·클릭·키 입력·스크롤·클립보드 접근·DB 조회·프로세스 주입을 하지 않습니다. 대화는 표준 입출력 JSON으로 앱에 전달하며 파일·로그로 원시 접근성 트리를 남기지 않습니다. 앱의 기존 최근 대화 저장 규칙은 동일합니다.

일반 채팅방 참여자 수, 입력란, 메시지 목록과 행, 메시지의 텍스트 또는 첨부 표식을 확인해 읽습니다. 단체방은 프로필·발신자 이름 컨트롤에서 발신자를 분리하며, 이름을 확인하지 못한 새 메시지는 생성을 중단합니다. 본문을 합친 윈도우 텍스트는 메시지로 추정하지 않습니다. 긴/중앙 말풍선 등 발신 방향을 구분할 수 없는 새 메시지는 생성을 중지합니다. 사진·파일 행은 첨부 표식으로 보존하고, 해석할 수 없는 행도 확인되지 않은 첨부로 남깁니다. 내용이 확인되지 않으면 오래된 텍스트만으로 초안을 생성하지 않습니다. 카카오톡 버전에 따라 UI Automation이 이런 정보를 제공하지 않을 수 있으며, 그 경우 이 버전에서는 수집할 수 없습니다. 최소화, 같은 제목의 창 여러 개, 구조 불명확, 시간 초과도 상태로 표시합니다. 읽기 시간 초과 시 작업자를 종료하고 다음 확인 때 새로 시작하며 이전 기록을 새 수신으로 처리하지 않습니다.

실패할 경우 `연결 설정 → Windows 구조 진단 저장`으로 JSON 파일을 저장할 수 있습니다. 진단에는 컨트롤 종류·클래스·부모 관계·패턴 지원 여부만 담습니다. 채팅방 제목·이름·본문·입력란 내용·화면 이미지·화면 좌표·런타임 식별자는 제외합니다. 저장 위치를 직접 선택하며 자동 업로드하지 않습니다. 이 파일은 실제 Windows 레이아웃을 보완하는 데 사용할 수 있습니다.

Codex 실행 파일은 공식 설치 기본 경로([공식 환경 변수 문서](https://learn.chatgpt.com/docs/config-file/environment-variables)), `CODEX_INSTALL_DIR`, PATH와 npm의 Windows 플랫폼 패키지에서 찾습니다. `codex.cmd`/`codex.ps1` 경로를 입력하면 같은 설치의 네이티브 `codex.exe`를 찾습니다. 셸을 거쳐 대화나 프롬프트를 인자로 조립하지 않습니다. 취소 시 Codex 하위 프로세스도 종료합니다. Windows 창에는 기본 최소화·최대화·닫기 버튼을 사용합니다.

```powershell
npm ci
npm run typecheck
npm test
npm run dist:win      # x64 NSIS 설치 파일
npm run dist:win:zip  # x64 압축 파일
```

Windows에서 `build:native`는 C# UI Automation 모듈을 실제로 컴파일하고 `list` JSON 요청의 응답을 확인하는 smoke check를 실행합니다. 카카오톡이 설치되지 않은 CI에서는 `not_running` 응답만 검증하므로 실제 대화 통합 테스트는 아닙니다. `.github/workflows/windows.yml`은 Windows 빌드·테스트·설치 파일 업로드를 구성하지만, 저장소에 푸시해서 워크플로가 실제 완료되기 전에는 통과했다고 간주하지 않습니다. 서명 인증서는 설정하지 않았습니다.


## 0.4.1 나와의 채팅 실제 대화 수동 생성

대화 모니터의 `실제 대화 초안 만들기`는 선택한 방을 다시 읽어 버튼을 누른 시점의 최근 텍스트 20개와 저장한 공통 프롬프트로 Codex를 실행합니다. 감지가 일시정지여도 연결을 읽을 수 있으면 사용할 수 있습니다. 실제 대화를 읽지 못하면 오류를 표시하고 가상 데이터로 대체하지 않습니다.

나와의 채팅도 수동 생성할 수 있습니다. 이 방의 마지막 메시지를 테스트 입력인 상대 메시지로 가정하며, 로컬에 보관된 원래 발신 방향은 바꾸지 않습니다. 일반 1:1 방은 마지막 메시지가 실제 상대 메시지여야 합니다. 초안에는 `실제 대화로 생성한 수동 초안`을 표시하고 실제 방 이름으로 앱에만 보관합니다. 전달 설정이 카카오톡이어도 이 수동 초안은 카카오톡으로 보내지 않습니다. 나와의 채팅에서 새 메시지마다 자동 생성하는 기능은 켜지지 않습니다.

고정된 가상 대화 시험은 `연결 설정 → 가상 대화로 Codex 연결 시험`으로 구분했습니다. 이는 모델·effort·CLI 연결 확인용입니다. 실제 대화 수동 생성과 화면의 진행 상태·결과 출처를 구분합니다. 공통 설정 변경·선택 방 전환/제거·기록 삭제·앱 종료 시 진행 중인 수동 생성은 취소합니다.


## 0.4.2 초안 완료 데스크톱 알림

자동 생성, 실제 대화 수동 생성(나와의 채팅 포함), 가상 대화 Codex 연결 시험이 완료되면 OS 데스크톱 알림을 띄웁니다. 실패하거나 취소된 생성에는 완료 알림을 띄우지 않습니다. 기본 알림음을 요청하며, 실제 소리와 배너는 운영체제 알림 허용·집중 모드·볼륨 설정을 따릅니다. 알림에는 대화방 이름과 완료 안내만 표시하고 메시지·초안 본문은 넣지 않습니다. 앱 실행 중 알림을 누르면 해당 초안을 선택하고 대화 모니터를 엽니다. 최소화된 앱도 복원합니다. 카카오톡 전송 완료를 기다리지 않고 로컬 초안 저장 직후 알립니다.

`연결 설정 → 초안 전달 → 데스크톱 알림 테스트`로 Codex나 실제 대화를 사용하지 않고 알림만 시험할 수 있습니다. OS가 알림 오류를 반환하면 화면에 안내하고, 저장된 초안은 그대로 유지합니다. OS가 배너를 조용히 숨기는 경우까지 감지할 수는 없으므로 시스템 알림 설정을 확인해야 합니다.

Mac 패키지는 알림 API 동작에 필요한 로컬 ad-hoc 서명을 적용합니다. Developer ID 공인 서명·공증과는 다릅니다. 앱 재서명 후 접근성 권한을 운영체제가 다시 요청할 수 있습니다. Windows는 설치 시 시작 메뉴 바로가기를 생성하고 `com.eddie.replynote` AppUserModelID를 사용합니다. Windows 알림 실기 검증은 별도 필요합니다. [Electron 공식 알림 문서](https://www.electronjs.org/docs/latest/tutorial/notifications)의 플랫폼 요구사항을 따릅니다.


## 0.4.3 초안 직접 수정

생성된 초안은 여러 줄을 입력할 수 있는 textarea로 표시합니다. 입력을 멈춘 뒤 약 0.5초 후 수정 내용을 자동으로 로컬에 보관하고 최근 초안에도 반영합니다. 저장 버튼은 표시하지 않습니다. 입력창에서 벗어나거나 `⌘S`/`Ctrl+S`를 누르면 즉시 저장합니다. `초안 복사`는 입력창의 현재 내용을 저장한 뒤 복사합니다. 저장 중·저장됨·저장 실패 상태를 표시합니다. 입력은 즉시 메인 프로세스로 전달하며 앱 종료 직전에도 대기 중인 내용을 저장합니다. 저장 실패 시 입력 내용은 메모리에 유지하고 오류를 표시합니다. 같은 실행 세션에서 방이나 초안을 바꾸는 동안에는 입력 중인 내용을 유지합니다. 최대 20,000자까지 입력할 수 있고 빈 초안은 복사하지 않습니다.

처음 생성된 원문·요청 모델·effort·기존 전달 상태는 보관하며 수정 시각을 기록합니다. 이미 나와의 채팅으로 전달된 초안을 수정해도 카카오톡 메시지를 변경하거나 다시 전송하지 않습니다. 수정본임을 화면에 표시합니다. 삭제됐거나 보관 한도를 벗어난 초안은 편집 저장으로 복구하지 않습니다.


## 0.4.4 새 버전 확인과 다운로드

패키징된 앱은 실행할 때와 실행 중 6시간마다 GitHub 공개 Releases의 최신 배포를 확인합니다. 새 버전과 현재 OS·아키텍처에 맞는 설치 파일이 모두 있으면 화면 상단에 다운로드 안내를 표시합니다. `연결 설정 → 앱 업데이트`, 앱 메뉴와 트레이의 `업데이트 확인…`에서도 수동 확인할 수 있습니다. 확인 요청에는 대화·프롬프트·사용자 토큰을 포함하지 않습니다. 개발 실행은 수동 확인만 가능하며 데모에서는 네트워크 조회를 하지 않습니다.

다운로드 버튼은 검증한 이 저장소의 설치 파일 URL을 기본 브라우저에서 엽니다. 이 버전은 업데이트 알림과 수동 교체를 지원하며 자동 설치·재시작은 하지 않습니다. Mac은 앱을 완전히 종료하고 응용 프로그램의 기존 앱을 새 앱으로 대치합니다. Windows는 트레이에서 종료한 뒤 새 설치 파일을 기존과 같은 위치에 설치합니다. 설정과 기록은 userData에 유지됩니다. Mac 손쉬운 사용 권한은 다시 요청할 수 있습니다.

파일이 없는 OS·아키텍처, 조회 제한, 연결 오류와 최신 상태를 구분합니다. 출시 전 드래프트와 prerelease는 업데이트 대상으로 사용하지 않으며 다운그레이드를 제안하지 않습니다. 기존 0.4.2 사용자는 이 기능을 포함한 버전을 한 번 수동 설치해야 합니다.

후속 배포 시 버전을 올리고 Mac 파일 `Reply-Note-버전-arm64-mac.zip`(Intel은 `x64`), Windows 파일 `Reply-Note-Setup-버전.exe`를 `v버전` GitHub Release에 모두 업로드한 뒤 공개하고 최신 릴리스로 지정하세요. 빌드의 artifactName 설정이 이 파일명을 생성합니다. 설치 파일 업로드가 완료된 뒤 공개해야 설치 파일 준비 중 안내를 피할 수 있습니다. 사이트 다운로드 버전도 `docs/app.js`와 `docs/index.html`에서 함께 갱신합니다.


## 단체방: 질문자별 초안

방마다 **초안을 만들어줄 질문자**와 **답하면 생성을 취소할 선생님**을 여러 명 등록합니다. 대화 모니터에서 방을 선택한 뒤 `이 방의 초안 대상`에 카카오톡 표시 이름을 한 줄에 한 명씩 입력하고 `참여자 설정 저장`을 누릅니다. 최근 대화에서 확인된 이름을 버튼으로 추가할 수도 있습니다. 내 메시지는 `나`로 표시하므로 직접 답했을 때도 취소하려면 선생님에 `나`를 등록하세요. 동일한 이름을 가진 참여자를 구분할 고유 ID는 수집하지 않으므로, 역할이 다른 참여자는 서로 다른 표시 이름을 사용해야 합니다. 저장하면 해당 방만 일시정지하고 재시작 시 새 기준부터 감지합니다. 기존 1:1 방은 참여자 지정을 켜지 않으면 기존 동작을 유지합니다.

- 등록된 질문자가 메시지를 보내면 질문 여부·본문 의미에 관계없이 생성합니다. 등록하지 않은 사람의 메시지는 문맥에만 사용합니다.
- 질문자별 마지막 메시지부터 10초 기다리고, 사람마다 별도 초안을 생성합니다. 같은 질문자의 연속 메시지만 대상 메시지로 묶습니다. 생성 중 같은 사람이 추가로 보내면 그 작업만 취소하고 다시 기다립니다.
- 등록된 선생님의 메시지가 오면 그 방의 모든 질문자의 대기·생성을 취소합니다. 누구의 질문에 답했는지 판별하지 않습니다. 한 번의 수집에서 선생님 메시지 뒤에 새 질문자 메시지가 있으면 그 이후 메시지는 새 작업으로 처리합니다.
- 완성된 초안은 삭제하지 않습니다. 감지 중 이후 선생님 메시지가 오면 `선생님 응답 있음`과 이름·감지 시각을 기록합니다. 질문이 해결됐다는 의미 판정은 아닙니다.
- 같은 방의 최근 텍스트 20개와 질문자별 대상 메시지를 모델에 전달합니다. 대상 메시지는 최대 20개로 제한합니다. 화면에는 질문자별 최신 초안 선택 버튼, 대상 메시지, 개별 대기·생성 상태를 표시합니다. 전체 초안 보관 한도는 기존처럼 20개입니다.
- 수동 생성은 마지막 메시지가 등록된 질문자의 메시지일 때 지원합니다. 생성 도중 대화가 바뀌면 결과를 폐기합니다. 수동 초안은 앱에만 보관합니다.
- 상대나 단체방에 자동 발송하지 않습니다. 기존 선택에 따라 앱에 보관하거나 나와의 채팅으로 전달하며, 본인용 전달에도 대상 질문자 이름을 포함합니다.

참여자 설정은 `state.json`의 `participantsByRoom`에 방별로 저장하며, 기존 1:1 데이터는 유지됩니다. 단체방은 참여자 수가 확인되고 발신자 이름을 분리할 수 있는 접근성 구조에서만 사용할 수 있습니다. 발신자 표시가 생략된 연속 말풍선은 읽은 범위 안의 직전 발신자를 이어받고, 새 프로필이 있는데 이름을 확인하지 못하면 추정하지 않습니다. **Mac·Windows 실제 단체방 레이아웃에서 발신자 추출은 별도 실기 검증이 필요합니다.** 합성 Windows 구조 테스트, 워크플로 테스트, Mac 네이티브 빌드, 격리된 Electron 데모 검증을 실제 카카오톡 통합 검증과 구분합니다.

```sh
npm run typecheck
npm test
npm run build
node scripts/test-macos-parsing.mjs # Mac 발신자·참여자 수 파싱 규칙 검사
node scripts/smoke-group-ui.mjs # 격리된 데모에서 질문자 2명·선생님 취소·완성 초안 표시 확인
```

데모는 실제 실행과 별도 프로필·잠금을 사용합니다. `npm run demo`에서 수학 수업방을 선택하고 민수·지우·선생님 메시지 버튼으로 흐름을 확인할 수 있습니다. 화면 검증 스크립트는 실제 대화·Codex·카카오 API를 호출하지 않고 임시 프로필을 종료 후 삭제합니다. 스크린샷은 기본 `/tmp/reply-note-group-ui-evidence`에 저장합니다.


## 0.4.5 Mac 수동 전송 후 최소화

초안 아래 `카톡방으로 전송`을 누르면 대상 방과 현재 수정한 본문이 확인창에 표시됩니다. `전송 후 최소화`를 직접 눌러야 전송 작업이 시작됩니다. Mac 일반 1:1 채팅과 나와의 채팅에 한해 제공하며, Windows·데모·가상 대화 시험·단체방에서는 사용할 수 없습니다. 실제 저장된 대상 방을 선택해야 합니다.

작업은 대상 창을 잠깐 복원·활성화하고, 채팅 종류·입력란·창 제목·포커스를 다시 확인합니다. 카톡 입력란이 비어 있어야 하며 기존 작성 내용을 덮어쓰지 않습니다. 카카오톡의 Enter 전송 설정을 기준으로 대상 프로세스에만 Return 한 번을 전달합니다. 마우스·클립보드·전역 키 입력은 사용하지 않습니다. 창 복원 없이 최소화를 계속 유지하는 백그라운드 전송은 지원하지 않습니다.

전송한 본문이 새 발신 메시지로 나타나고 입력란이 비워졌는지 확인한 뒤 창을 다시 최소화합니다. 결과 확인이 불가능해도 자동 재시도하지 않고 최소화하며 `확인 필요`로 남깁니다. 복원한 뒤 전송 전 검증에 실패한 경우에도 최소화를 시도합니다. 최소화 자체가 실패하면 그 사실을 결과에 표시합니다. 전송 중 포커스가 바뀌면 Return을 보내기 전에 중단합니다.

전송 시도 기록을 디스크에 먼저 저장합니다. 중복 클릭·동시 전송·이미 전송한 동일 본문을 차단하고, 전송 중 앱이 종료되면 재시작 후 결과 불명으로 취급합니다. 결과 불명 초안은 앱에서 다시 보낼 수 없으므로 카카오톡에서 먼저 확인해야 합니다. 실패가 명확히 확인된 경우에만 사용자가 다시 시도할 수 있습니다. 초안 편집은 메시지를 자동으로 전송하거나 기존 카카오톡 메시지를 수정하지 않습니다.

타입 검사·자동 테스트·Swift/Node-API 빌드와 입력 없는 native 보호 경로는 확인했습니다. 앞서 수동 GUI 시험에서 포그라운드 Enter 전송의 입력란 비움/행 증가와 최소화 동작은 각각 확인했지만, 새 앱의 실제 전송→본문 확인→최소화 전체 경로를 추가 실메시지로 검증한 것은 아닙니다.


## 0.4.6 전송 후 최소화 확인 타이밍

사용자가 지정한 실제 1:1 방에서 승인한 테스트 문구 한 건을 새 native 전송 경로로 보냈습니다. native 응답은 새 발신 본문 일치와 입력란 비움을 확인해 `sent`를 반환했고, 별도의 OS 확인에서도 창이 최소화되어 있었습니다. 그러나 최소화 요청 직후에는 AXMinimized가 아직 false라 성공한 최소화를 실패로 안내하는 문제가 있었습니다. 최대 1.2초 동안 상태 반영을 기다린 후 판정하도록 수정했습니다. 이 수정 때문에 추가 메시지를 보내지는 않았습니다.


## 0.4.7 다중 참여자 기능 통합 점검

참여자 규칙을 저장한 1:1 방에서도 수동 생성이 등록된 질문자를 답변 대상으로 지정하도록 수정했습니다. 생성 중 해당 방 대화가 바뀌면 수동 결과를 폐기합니다. 단체방의 질문자·선생님 설정이 비어 있으면 수동 생성도 중단합니다. 가상 대화 연결 시험은 실제 참여자/답변 대상 설정을 가져오지 않습니다.

참여자 설정 입력창은 일시적인 연결 끊김이나 단체방 판별 변경 때 입력 중인 이름을 초기화하지 않습니다. 방을 바꾸거나 저장된 설정이 변경된 경우에만 입력값을 다시 불러옵니다. 초안 본문은 자동 저장하지만 참여자 규칙은 `참여자 설정 저장`으로 적용하며 해당 방의 감지를 정지합니다.

통합 테스트에서 방별 설정·문맥 격리, 질문자별 대기, 선생님의 같은 방 작업 취소, 자동 저장 후 대상 메시지·선생님 응답 표시 보존, 1:1 직접 전송이 다른 방의 대기를 취소하지 않는 것을 확인했습니다. 별도 데모 프로세스의 실제 textarea에서 미저장 이름을 입력하고 연결 오류/복구를 재현해 보존되는 것도 확인했습니다. 데모 저장 규칙과 실제 사용자 state.json이 바뀌지 않았고 실제 메시지·Codex 호출은 사용하지 않았습니다.

직접 전송은 여전히 Mac 1:1/나와의 채팅용이며 단체방 직접 전송은 비활성화합니다. 실제 여러 명이 참여한 카카오톡 단체방의 실기 수신·이름 식별은 이 통합 테스트와 별도 검증이 필요합니다.


## 0.4.8 확인창 없이 수동 전송

초안의 `카톡방으로 전송` 버튼을 누르면 현재 편집 중인 본문을 바로 전송합니다. 별도의 확인창과 성공 토스트는 표시하지 않으며 결과는 초안 아래에 남깁니다. 전송 실패나 결과 불명 안내는 유지합니다. 전송 후 카카오톡 창을 다시 최소화하는 동작과 중복 전송 차단은 유지합니다.


## 0.4.9 최소화 상태에서 수동 전송 준비

최소화 해제 요청 직후 대화를 읽던 경로를 수정했습니다. AXMinimized 해제·카카오톡 활성화·대상 창 포커스가 안정적으로 확인된 뒤 대화를 읽고, 복원 직후 잠깐 발생하는 AX 읽기 오류는 준비 단계에서만 기다립니다. 입력란 포커스도 반영을 기다리며, 전송 요청의 native 작업 시간은 읽기보다 길게 확보합니다. Enter는 여전히 한 번만 보내며 전송 결과 불명 시 재시도하지 않습니다.

`node scripts/test-macos-send-preparation.mjs "열린 방 제목"`은 실제 열린 대상 창을 최소화하고, 제품 코드의 복원 함수·native 대화 읽기·입력 포커스까지 확인합니다. 본문 변경이나 키 전송은 하지 않고 원래 최소화 상태와 앞에 있던 앱을 복구합니다. Mac에서 이 준비 경로를 두 차례 확인했습니다. 이번 수정 후 실제 메시지 전송은 추가로 시험하지 않았습니다.


## 0.4.10 수동 전송 속도 개선

전송 전에는 고유한 대상 창·1:1 종류·입력란·대화 목록을 확인하고 기존 행의 AX 참조를 보관합니다. 과거 60개 행의 본문·이름·시간을 해석하지 않습니다. 전송 후에는 새 행만 최신순으로 확인해 발신 방향과 본문 일치, 입력란 비움을 검증합니다. 고정된 8개 행 제한은 사용하지 않으며 기존 동일 본문을 새 전송으로 간주하지 않습니다. 기존 행은 일반 수신 ID 캐시와 분리해 보관합니다. 대화 목록을 읽지 못하면 키를 보내지 않습니다. 일반 수신·참여자 추적의 문맥 범위는 유지합니다.

MacReader에서 수동 전송은 대기 중인 read/list보다 우선 처리됩니다. 진행 중인 native 요청은 중단하지 않고 동시에 다른 요청도 실행하지 않습니다. native 응답 지연이나 전송 결과 불명 시 자동 재전송하지 않습니다.

자동 테스트와 실제 창의 비전송 시험으로 검증합니다. `node scripts/test-macos-send-preparation.mjs "열린 대상 방 제목" --send-path`은 제품 전송 준비 함수를 측정하고, 기존 메시지로 발신 판별·과거 동일 본문 제외·다른 본문/수신 메시지 제외를 검사합니다. 메시지 입력이나 Enter 이벤트는 보내지 않습니다. 실제 발송 전체 시간은 별도 실기 시험이 필요합니다.


## 질문에 원문·사진·문서 연결

대화 속 질문 메시지 아래 **원문 보기·연결**을 펼칩니다. 별도의 원문·사진·파일 연결 섹션이나 질문 선택 단계는 없습니다. 수집해둔 대화에서 원문을 최대 10개 선택하거나, 수집되지 않은 원문·보충 설명을 직접 입력할 수 있습니다. `사진·파일 선택` 또는 파일 드래그로 자료를 붙인 뒤 **이 질문과 자료로 초안 만들기**를 누릅니다. 선택한 과거 질문에 대해 현재 방의 최근 대화와 연결한 자료를 참고하여 앱 전용 초안을 만듭니다. 자료가 바뀌면 해당 질문자의 진행 작업을 취소하며, 생성 중 대화가 바뀌면 수동 초안을 폐기합니다.

| 형식 | 처리 범위 |
| --- | --- |
| PNG, JPG/JPEG, WebP | 이미지를 정규화해 모델에 전달합니다. 긴 변 최대 2,000px로 축소합니다. |
| PDF | 최대 5쪽의 텍스트와 각 페이지 이미지를 함께 전달합니다. 스캔본·삽입 그림도 페이지 이미지로 참고할 수 있습니다. |
| Word DOC, DOCX | 본문 텍스트를 추출합니다. 삽입 그림·수식·배치는 누락될 수 있습니다. |
| 한글 HWP 5.x, HWPX | 본문·표 안의 문단 텍스트를 추출합니다. 수식·그림·배치는 누락될 수 있습니다. |
| TXT, MD, CSV | UTF-8·UTF-16LE 또는 한국어 EUC-KR 텍스트로 읽습니다. |

파일당 최대 10MB, 질문 하나당 최대 4개이며, 한 초안에 전달하는 이미지·PDF 페이지는 합계 최대 12장입니다. 문서 텍스트는 파일별 앞 40,000자까지 사용하고 잘림을 표시합니다. 암호·배포용·보호 문서, 손상 파일, 지원하지 않는 형식은 읽기 실패를 표시합니다. Word/한글의 수식이나 그림이 중요하면 PDF 또는 사진으로 연결하세요. 연결한 원문·문서 텍스트·이미지는 초안 생성 시 OpenAI에 전달됩니다. 내용 속 명령은 참고 데이터로만 취급하도록 지시하고, 기존 읽기 전용 Codex 실행을 유지합니다. 이미지 입력은 설치된 CLI의 `--image`를 사용합니다([공식 이미지 입력 문서](https://learn.chatgpt.com/docs/image-inputs?surface=cli)).

자료는 **방과 질문 메시지 ID**에 연결합니다. 같은 사람의 다음 질문에 이전 파일을 자동 적용하지 않습니다. 생성된 초안에는 사용한 원문·설명·파일 이름과 읽기 범위를 남깁니다. 이후 자료 연결을 바꿔도 이미 생성한 초안의 출처 표시는 당시 내용으로 유지합니다. 상대나 단체방에 파일을 자동 전송하는 기능은 추가하지 않습니다.

`state.json`의 `archiveByRoom`에는 방별 수집 대화를 최대 500개·20만 자까지 누적 보관합니다. 카톡을 자동 스크롤해 전체 과거 내역을 가져오는 기능이나 카톡 답장 원문·캐시 파일 자동 매칭은 포함하지 않습니다. 앱이 수집하지 못한 원문은 직접 붙여넣어 연결합니다. Mac의 메시지 ID는 앱 실행별로 구분해 재시작 후 다른 메시지에 자료가 잘못 붙지 않게 합니다.

선택한 파일은 앱 데이터의 `question-materials/임의ID/`로 복사하고, 문서 텍스트와 질문별 연결 정보는 `question-materials/contexts.json`에 로컬 평문으로 저장합니다. 질문별 자료 연결은 최대 100건을 보관합니다. 원본 파일을 이동해도 앱 사본으로 분석할 수 있습니다. 파일 연결 해제·방 제거·기록 삭제는 앱 사본을 정리하며 사용자가 선택했던 원본 파일은 유지합니다. 문서 읽기는 별도 작업 스레드에서 실행하고 25초를 넘으면 중단합니다.

검증은 파서·문맥 분리·취소·출처 보존 테스트, Electron에서 실제 파일 드롭과 파싱, 가상 이미지의 실제 Codex 응답으로 구분했습니다. 공개 프로젝트의 실제 DOC와 HWP 샘플도 본문 추출을 확인했습니다. 실제 카톡의 답장/첨부파일 자동 연결을 검증한 것은 아닙니다.

```sh
npm run typecheck
npm test
npm run build
REPLY_NOTE_TEST_MATERIALS=1 node scripts/smoke-group-ui.mjs
```

파일 드롭 검증은 임시 데모 프로필에 생성한 가상 PNG·PDF·DOCX·HWP·HWPX를 사용합니다. 실제 카톡 대화나 사용자 파일을 읽지 않으며 데모에서는 모델을 호출하지 않습니다. HWP 5.x 파싱은 [한컴의 공개 형식 설명](https://tech.hancom.com/python-hwp-parsing-2/)에 따라 BodyText 레코드를 읽고, Word DOC는 [word-extractor](https://github.com/morungos/node-word-extractor)를 사용합니다.

Mac 테스트 패키지는 `release/materials-preview/mac-arm64/Reply Note.app`에 별도로 만들었습니다. 기존 앱을 종료한 뒤 실행할 수 있습니다. 패키징된 앱에서도 동일한 가상 파일 드롭·파싱·초안 출처 검증을 실행했습니다.

```sh
REPLY_NOTE_TEST_MATERIALS=1 REPLY_NOTE_TEST_APP="$PWD/release/materials-preview/mac-arm64/Reply Note.app/Contents/MacOS/Reply Note" node scripts/smoke-group-ui.mjs
```


## 0.4.11 사람별 프롬프트

대화 모니터에서 `사람별 프롬프트`를 펼치고 대상을 골라 말투·호칭·존댓말 지침을 입력한 뒤 `개인 프롬프트 저장`으로 적용합니다. 1:1 방에서는 상대방 지침을, 참여자 지정 방에서는 사람별 지침을 저장합니다. 동일한 표시 이름도 방이 다르면 별개이며 지침은 이 PC에 보관합니다. 비워서 저장하면 해당 지침이 삭제되어 공통 프롬프트만 적용합니다. 사용자별 최대 5,000자, 방별 최대 100명입니다.

공통 프롬프트를 유지하고 답변 대상에게 해당하는 개인 지침만 추가합니다. 말투·존댓말·호칭이 충돌하면 개인 지침을 우선합니다. 자동 생성, 실제 대화 수동 생성, 선택한 질문 생성에 적용하며 가상 연결 시험에는 개인 지침을 넣지 않습니다. 저장하면 해당 방의 대기·생성을 취소하고 일시정지하므로 감지를 다시 시작해야 합니다. 다른 방의 감지는 유지합니다. 다른 사람으로 전환할 때 미저장 입력도 보존합니다.

검증: 프로필 선택·공통 지침 병행·그룹 대상 분리·방별 동명이인 분리·설정 유지·재시작/삭제·유효성 검사·실제 생성 경로의 프롬프트 전달을 자동 테스트했습니다. 별도 데모 UI에서 존댓말/반말 지침 저장, 전환 시 미저장 입력 보존, 1:1 방 설정과 빈 내용 삭제를 확인했습니다. 실제 대화 전송이나 실제 Codex 호출은 수행하지 않았습니다.


## 최근 대화 안의 사진·파일 감지

최근 20개는 **텍스트와 첨부 표식을 합친 메시지 20개**입니다. 사진·파일만 있는 행도 건너뛰지 않고 순서, 발신자(확인된 경우), 표시 시각, 사진/파일 구분과 노출된 파일 이름을 보관합니다. 해석할 수 없는 비텍스트 행은 `확인되지 않은 첨부`로 보존합니다. 발신자를 확인하지 못하면 기존처럼 감지를 보류합니다. 알려진 날짜·읽음 구분 행과 프로필 이미지는 메시지 첨부와 구분합니다.

대화의 첨부 카드에는 `내용 확인 필요` → `자료 읽기 완료` → `초안에 사용됨`을 표시합니다. `카톡에서 가져오기`로 원본을 가져오거나 그 첨부의 `직접 파일 선택` 또는 파일 드래그로 자료를 연결합니다. `연결 확인`을 펼쳐 연결된 파일의 내용·주의사항을 보고 연결을 해제할 수 있습니다. 나와의 채팅이나 다른 참여자가 보낸 첨부도 해당 메시지에서 직접 처리합니다. **보충 자료를 업로드하기만 한 것은 특정 카톡 첨부를 읽었다고 간주하지 않습니다.** 사진은 실제 이미지 데이터가 필요하며 묶음 사진은 알려진 장수만큼 준비되어야 합니다. Word·한글 등 기존 문서의 읽기 범위 안내는 유지합니다.

최근 20개, 답변 대상 메시지, 해당 질문에 선택한 원문 중 미확인 첨부가 하나라도 있으면 자동·수동 생성을 모델 호출 전에 보류합니다. 처음 연결할 때 이미 있던 사진과 다른 참여자가 보낸 첨부도 포함합니다. 생성 도중 새 미확인 첨부가 오면 작업을 중단하고, 전달 직전 재확인에서도 결과를 폐기합니다. 등록된 선생님이 보낸 사진·파일은 기존 규칙대로 방 전체 작업 취소 신호입니다. 이전에 완성된 초안은 보관하고, 새 생성을 보류 중임을 표시합니다.

명시적으로 파일을 연결해 읽은 **같은 방의 같은 메시지·첨부**는 후속 질문에서도 참고할 수 있습니다. 다른 질문의 개인 설명이나 연결하지 않은 보충 파일을 함께 가져오지는 않습니다. 메시지 발신자·본문·첨부 종류·파일 이름 등이 바뀌면 예전 연결을 그대로 사용하지 않으며, 연결 해제 시 다시 확인 필요 상태가 됩니다. 첨부 감지 표식과 파일 출처 연결은 로컬 기록 및 초안 출처에 보관합니다.

카톡 파일을 자동 다운로드하거나 캐시 경로를 추정해 가져오는 기능은 포함하지 않습니다. 실제 파일 확보는 기존 파일 선택/드래그 방식입니다. Mac/Windows 접근성 레이아웃에 따라 첨부와 발신자를 어디까지 노출하는지는 실제 카톡에서 별도 확인해야 합니다. 이 변경은 합성 Windows 트리, Mac 순수 파싱 규칙·네이티브 빌드, 모델 호출 차단·중단 테스트, 격리된 Electron 데모로 검증합니다.

```sh
npm run typecheck
npm test
node scripts/test-macos-parsing.mjs
npm run build
REPLY_NOTE_TEST_MATERIALS=1 REPLY_NOTE_TEST_MEDIA=1 node scripts/smoke-group-ui.mjs
```

데모의 `사진 메시지 추가`와 `파일 메시지 추가`로 텍스트 없는 메시지 감지·생성 보류·파일 출처 연결·초안 사용 표시를 확인할 수 있습니다.


## 0.4.12 답장 편집창 키보드 전송

답장 내용 textarea에서 Enter는 `카톡방으로 전송`과 동일하게 현재 내용을 전송하고, Shift+Enter는 줄바꿈합니다. 버튼이 비활성화된 경우 키보드로도 전송하지 않으며, 한글 등 IME 조합 확정 Enter와 키 자동 반복은 전송하지 않습니다. 기존 Cmd/Ctrl+S 저장은 유지합니다. 자동 전송 기능이 아니라 사용자가 Enter를 눌렀을 때의 수동 전송입니다.

## 0.4.13 지시를 입력해 초안 다시 작성

실제 대화의 초안 아래 `초안을 어떻게 바꿀까요?`에 지시를 적고 `지시대로 다시 만들기`를 누르면 현재 편집한 초안, 최근 대화 최대 20개, 공통·개인 프롬프트와 질문에 연결된 자료를 참고해 새 초안을 만듭니다. 이번 지시가 말투·형식과 충돌하면 이번 지시를 우선하며 저장된 공통·개인 설정은 바꾸지 않습니다. 지시는 요청마다 최대 5,000자입니다.

진행 중 `재작성 취소`로 중단할 수 있습니다. 원본을 덮어쓰지 않고 별도 새 초안에 부모 초안 ID와 재작성 지시를 기록합니다. 새 초안에 다시 지시해 반복할 수 있으며, 자동으로 카카오톡에 전송하지 않습니다. 재작성 지시 입력칸의 Enter는 줄바꿈이고, 기존 답장 본문 편집칸의 Enter 전송·Shift+Enter 줄바꿈은 유지합니다.

단체방은 원본 초안의 답변 대상을 유지합니다. 생성 중 대화가 바뀌면 결과를 폐기하고, 선생님 응답·설정 변경·방 전환·전송·기록 삭제 등 기존 취소 신호에 재작성도 함께 취소됩니다. 원본에 이미 표시된 선생님 응답은 새 초안에도 유지합니다. 실제 방이 연결되지 않거나 필요한 자료가 미연결이면 임의의 문맥으로 대체하지 않고 중단합니다. 가상 연결 시험 초안은 이 기능에서 제외합니다.

검증: 자동 테스트와 별도 데모 UI에서 수정된 본문 반영, 원본 유지, 새 결과의 미전송 상태, 공통·개인 지침 유지, 지시의 단발 적용, 그룹 대상 보존, 변경/취소 결과 폐기, 재작성의 연속 실행을 확인했습니다. 실제 카카오톡 전송이나 실제 Codex 호출은 하지 않았습니다.

## 카톡 첨부 원본 가져오기 · macOS 실험 기능

감지된 사진·파일 옆 `카톡에서 가져오기 · 실험`을 누르면 카톡의 해당 메시지에서 원본을 저장하고, 읽은 자료를 그 메시지에 연결합니다. 나와의 채팅의 보낸 첨부도 지원합니다. 실행 중 카톡 창이 잠깐 활성화되므로 다른 카톡 작업을 마친 뒤 사용하세요. 사진 한 장과 단일 파일을 지원하며 묶음 사진·정체가 불확실한 첨부는 기존 자료 연결을 사용합니다. 현재는 버튼을 눌러 가져오는 방식이며 모든 첨부를 백그라운드에서 자동 다운로드하지 않습니다.

최근 수집 범위에 있는 정확한 원본 메시지를 다시 확인하고 빈 전용 작업 폴더에 저장합니다. 파일명, 단일 일반 파일 여부, 10MB 제한과 저장 후 원본 메시지를 검증한 뒤 기존 PNG/JPG/WebP·PDF·DOC/DOCX·HWP/HWPX·TXT/MD/CSV 분석기로 연결합니다. 성공 후 임시 저장 폴더를 정리합니다. 만료·권한 부족·대화 변경·저장 실패 시 다른 파일을 추측해서 연결하지 않으며 내용 미확인 상태를 유지합니다. 새 메시지를 보내거나 파일을 업로드하는 기능은 아닙니다.

실제 나와의 채팅에서 카톡 UI의 PDF 원본 저장과 사진 뷰어의 JPEG 원본 저장을 각각 확인했습니다. 새 앱 버튼의 연결·분석·출처 보존은 별도 데모 UI로 검증했으며, 네이티브 자동 조작을 통한 실제 카톡의 전체 과정은 추가 실기 검증이 필요합니다. 실제 검증에 사용한 자료를 모델에 전송하지 않았습니다. 데모 추가 검증은 `REPLY_NOTE_TEST_MATERIALS=1 REPLY_NOTE_TEST_MEDIA=1 REPLY_NOTE_TEST_ACQUIRE=1 node scripts/smoke-group-ui.mjs`로 실행합니다.

나와의 채팅 수동 생성에서는 마지막 메시지를 질문으로 해석하더라도 첨부 원본의 실제 발신 방향·발신자 정보로 연결 상태를 검증합니다. 사진만 마지막에 남아 있는 경우에도 이미 가져온 원본을 미연결 자료로 오인하지 않습니다. 이 경로를 포함해 자동 테스트 184개와 검증용 패키지 데모 UI 검사를 통과했습니다.

사진·파일 연결은 대화의 각 첨부 메시지에서 처리하며, 실패 시 그 메시지에 오류와 다시 가져오기 버튼을 표시합니다. 질문의 원문·설명 편집은 메시지 아래에서 필요할 때 펼칩니다. 기존에 저장한 원문·설명·첨부와 초안 출처 정보는 유지합니다.

## 0.4.14 GitHub 배포

GitHub 다운로드용 Mac Apple Silicon ZIP과 Windows x64 설치 파일을 0.4.14로 갱신합니다. 사진·파일 메시지의 직접 연결과 질문별 원문 편집 화면을 포함합니다. 실제 Windows 카톡 연결과 macOS 실험적 원본 가져오기 전체 과정의 검증 한계는 릴리즈 설명을 따릅니다. 공개 다운로드 사이트는 `docs/`이며 로컬 앱 소스와 별도로 관리됩니다.

Windows 설치 파일을 macOS에서 교차 빌드할 때는 `@napi-rs/canvas-win32-x64-msvc@1.0.10`이 `node_modules`에 있어야 합니다. 해당 플랫폼 패키지는 일반 macOS `npm ci`에서 생략됩니다. 배포 전 `npm install --no-save --package-lock=false --ignore-scripts --force @napi-rs/canvas-win32-x64-msvc@1.0.10`으로 빌드용 패키지를 준비하고, 생성된 Windows app.asar에 `skia.win32-x64-msvc.node`가 포함됐는지 확인합니다. Windows에서 직접 빌드할 때는 일반 `npm ci`가 해당 플랫폼 패키지를 설치합니다.
